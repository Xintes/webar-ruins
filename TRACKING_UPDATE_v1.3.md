# WebAR — исправление мигающей привязки (v1.3)

Исправление поверх текущего репозитория `Xintes/webar-ruins`.

## Установка

Скопируйте содержимое папки `track/` из этого архива поверх существующей папки `track/` в репозитории.

Заменяются `track/main.js` и `track/index.html`, добавляется `track/motion.js`. HTML изменён также для принудительного обновления кеша JavaScript (`?v=13`). На сервере Render ничего менять не требуется. Выполните GitHub Desktop → Commit → Push origin, затем обновите страницу на телефоне. При необходимости откройте сайт в режиме инкогнито, чтобы не использовать кешированную версию `main.js`.

Готовая ссылка: https://xintes.github.io/webar-ruins/track/?api=https%3A%2F%2Fwebar-ruins.onrender.com

## Что изменено

- Вместо жёсткого тайм-аута 1500 мс — адаптивное удержание 4,5–9 с, привязанное ко времени последнего запроса.
- При одном отказе распознавания сохраняем предыдущую позицию. После двух последовательных отказов плавно скрываем стену.
- Кадры уменьшаются до 840 px по ширине для уменьшения нагрузки на сеть и бесплатный Render.
- Дополнительно: лёгкое локальное отслеживание небольшого сдвига изображения, без OpenCV.js и нейросети, на изображении 256 px. Может уменьшить отставание между ответами сервера при небольших движениях камеры.
- Сглаживание положения и плавное исчезновение.
- Превышение 16 секунд на запрос вызывает отмену, а не бессрочное зависание.
- Сохранён режим проверки фотографии, работа с API, CORS, показ зоны и загрузка эталонов на прежнем сервере.

## Ограничения

Это всё ещё 2D наложение с гомографией, НЕ устойчивый 6DoF AR и НЕ полная замена SLAM. При сильном движении телефона, повороте камеры, изменении глубины и обходе объёмной башни локальная оценка сдвига может ошибаться. Стена должна исчезать при надёжно подтверждённой потере объекта. Настоящее решение для реального объекта потребует локального оптического потока с моделированием движения/3D позы, калибровки и дополнительных эталонных кадров.
