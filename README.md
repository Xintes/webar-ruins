# WebAR: массив 3D-объектов относительно кубика

Это продолжение работающего проекта `xintes/webar-ruins`. Сохраняется прежний режим `building`, добавлен режим `objects` для цепочек примитивов и собственных `.glb`.

## 1. Установить поверх существующего проекта

1. Сохраните резервную копию работающей версии (или сделайте отдельную ветку в GitHub Desktop).
2. Перенесите файлы из этого архива **в корень** своего проекта `webar-ruins`, согласившись с заменой существующих файлов.
3. В GitHub Desktop убедитесь, что появились изменения `app.js`, `settings.js`, `index.html`, `README.md` и новый `objects.js`.
4. Сделайте коммит, затем `Push origin`. Уже настроенный GitHub Pages развернёт обновлённый сайт по прежней ссылке:
   https://xintes.github.io/webar-ruins/

## 2. Первый тест — без белого куба

Пока `settings.js` использует стандартный `.mind`-файл из примера MindAR. Откройте на другом экране изображение:

https://cdn.jsdelivr.net/gh/hiukim/mind-ar-js@1.2.5/examples/image-tracking/assets/card-example/card.png

На телефоне откройте ваш WebAR-сайт и разрешите камеру. Рядом со стандартным изображением должна появиться цепочка из 5 разноцветных 3D-кубов. Не нужно пока ничего скачивать или компилировать.

## 3. Тест с реальным белым кубиком

MindAR не умеет надёжно отслеживать гладкую белую поверхность: на ней нет узнаваемых визуальных особенностей. Для демонстрации приклейте **к одной грани** контрастную картинку с мелкими разнообразными деталями. Желательно, чтобы она занимала практически всю грань.

1. Снимите ровно эту грань почти фронтально при хорошем освещении, чтобы рисунок был чётким. Не включайте большой фон в кадр. По возможности компилируйте исходную картинку наклейки — она будет чище, чем фотография с перспективой.
2. Откройте https://hiukim.github.io/mind-ar-js-doc/tools/compile
3. Загрузите картинку и нажмите `Start`, затем `Download`.
4. Переименуйте результат в `targets.mind`, положите в `assets/targets.mind`.
5. В `settings.js` измените `targetFile` на `"./assets/targets.mind"`.
6. `Commit`, `Push origin`. Проверьте на телефоне с реальным кубом.

Кубик должен оставаться на одном месте, а камера — видеть наклейку. Положение других объектов рассчитывается **от плоскости этой грани**, а не от автоматически найденного объёмного центра куба.

## 4. Настроить количество и направление объектов

Все настройки в `settings.js`, массив `arrays`:

- `type`: `box`, `sphere`, `cylinder`, `cone`, `glb`.
- `count`: число объектов.
- `start: {x, y, z}`: центр первого объекта относительно рисунка.
- `step: {x, y, z}`: смещение каждого следующего объекта.
- `size`: размеры примитива; у сферы `size.x` — диаметр.
- `colors`: чередующиеся цвета для примитивов.
- `rotation`: углы в градусах.
- `enabled: false`: цепочка выключена.

Примеры:

```js
step: { x: 0.45, y: 0, z: 0 }    // вправо
step: { x: -0.45, y: 0, z: 0 }   // влево
step: { x: 0, y: 0.45, z: 0 }    // вверх
step: { x: 0, y: 0, z: -0.45 }   // за плоскость рисунка
step: { x: 0.45, y: 0, z: -0.45 } // диагональ вправо и назад
```

В локальных координатах +X — вправо на картинке, +Y — вверх, +Z — от картинки к камере (при фронтальном взгляде). Отрицательный Z уводит объекты за плоскость картинки. Это не «на север», не направление относительно телефона: ориентация следует рисунку, даже если повернуть кубик.

### Привязка размеров к физическому миру

1 единица координат соответствует ширине распознанного изображения. Если картинка наклейки шириной **10 см**, шаг `x: 0.45` — примерно **4,5 см** в реальном мире, пока цель корректно отслеживается. Если вы хотите 20 см, поставьте `x: 2`.

**Осторожно:** у `modelFile`/`glb` входные размеры из Blender преобразуются масштабом `scale`. Если Blender-модель построена в метрах, а изображение в реальности 0.1 м в ширину, начальный `scale` для натуральной величины может быть `1 / 0.1 = 10` (без учёта локальной геометрии и исходного масштаба объекта).

## 5. Загрузить свои модели .glb

1. Экспортируйте статический объект из Blender в формате `glTF Binary (.glb)`.
2. Поместите его в `assets/my-object.glb` (или другое имя, исправив `file`).
3. В третьем элементе `arrays` установите `enabled: true` и при необходимости `count`, `start`, `step`, `scale`, `rotation`.
4. При необходимости отключите примитивы через `enabled: false` в первом элементе массива.
5. Повторите GitHub Desktop → `Commit` → `Push origin`.

Движение и анимация пока не реализованы: `.glb` должен быть статическим (без скелетного рига). Для тяжёлых моделей уменьшайте `count`. Лимит в коде — 250 объектов, это не гарантия хорошей скорости.

## 6. Настройка сцены на телефоне

Откройте:

https://xintes.github.io/webar-ruins/?edit=1

Панель изменяет `SETTINGS.transform` — **общие** координаты, масштаб и углы всех цепочек. Нажмите «Скопировать настройки» и перенесите их в `settings.js` (не заменяя `arrays`). Количество, шаг и тип каждого объекта меняются только в `arrays`. Настройки `?edit=1` сохраняются локально в браузере; если после обновления осталась прежняя настройка, нажмите «Сбросить».

## 7. Ограничения

- **Без GPS и внешнего приложения** — да, через HTTPS-сайт.
- **Без распечатанной картинки для реальных руин** — возможно, если у фасада достаточно собственных узнаваемых деталей.
- **Без рисунка на полностью белом кубике** — этот прототип устойчиво работать не должен: недостаточно деталей для MindAR image tracking.
- При потере рисунка из кадра система скрывает привязанные объекты. Для постоянного удержания большого виртуального сооружения потребуется другой способ пространственной локализации (VPS/SLAM).
- Привязка к **одной плоской грани**, а не полноценная модель физического куба: не ожидайте стабильного распознавания со всех сторон.

Документация: https://hiukim.github.io/mind-ar-js-doc/quick-start/compile/ и https://hiukim.github.io/mind-ar-js-doc/more-examples/threejs-image/
