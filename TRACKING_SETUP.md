# WebAR /track — автоматическое распознавание башни без меток

Это расширение проекта `webar-ruins`: предыдущие `/`, `/cv/`, `/wall-lab/` сохранены.

## Что уже реализовано

- Привязка по **настоящему изображению камеры**: OpenCV SIFT (или ORB при отсутствии SIFT) ищет особенности опорного фото, сопоставляет их и оценивает гомографию через RANSAC.
- При наличии достаточного количества пространственно распределённых совпадений браузер проецирует прозрачное наложение стены в текущий кадр. При потере ориентира скрывает реконструкцию.
- Можно хранить **несколько подготовленных ракурсов** одной обзорной зоны; сервер автоматически выбирает наиболее подходящий. Никаких нейросетей, QR, наклеек, GPS.
- Эксперимент с фотографией: рабочий тест регистрации на исходном снимке из чата, но **не подтверждение** работы с реальной башней. Для реальной сцены требуется полевое тестирование.

ВАЖНО: первая версия сопоставляет плоские проекции. **Это не точная 6DoF AR-привязка**: при сильном движении вправо-влево вокруг цилиндрической башни возникает ошибка параллакса. В ограниченной зоне обзора её можно уменьшить, приготовив несколько референсов. Для точной 3D-геометрии нужен следующий шаг: реальные 3D-точки объекта, калибровка камеры и OpenCV `solvePnP` + отслеживание между серверными запросами.

## Запуск Windows (локально)

**Для нового ПК проще:** из корня проекта запустите двойным кликом `INSTALL_WINDOWS.bat` (устанавливает зависимости) и затем `START_WINDOWS.bat` (запускает сайт). Скрипты сами переходят в правильную папку. Python 3.12 должен быть установлен, команда `py` — доступна.

Альтернатива через PowerShell:

1. Распаковать архив так, чтобы в одной папке были `server`, `track`, `wall-lab`.
2. Открыть **PowerShell из этой папки** (через адресную строку Проводника, набрав `powershell`), а не из `C:\Windows\system32`.
3. Установить Python 3.12, если его нет. На Windows команда `py -3.12` работает даже если `python` не добавлен в PATH.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt
cd server
..\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Если ранее `pip` упирался в нерабочий proxy, попробуйте из папки **корня проекта**:

```powershell
.\.venv\Scripts\python.exe -m pip --isolated install -r server\requirements.txt
```

`--isolated` игнорирует переменные окружения и пользовательский конфиг pip. Если и это не помогает, проверять сетевые настройки/WinHTTP proxy отдельно; не выключать безопасность и SSL-проверку.

Открыть: **http://localhost:8000/track/**. Работает с обычной веб-камерой ПК, HTTPS не нужен благодаря исключению для `localhost`.

## Быстрая проверка без башни и без веб-камеры

1. На `/track/` выбрать «Проверить фотографию».
2. Выбрать `wall-lab/reference.png` из распакованного архива.
3. Увидеть на фото башни наложенную стену и статус `Башня распознана`.
4. Можно открыть фото на другом мониторе, включить веб-камеру и направить на экран. Тест проверяет привязку к ориентиру, не качество реального AR на улице.

`server/track_refs/tower/wall-overlay.png` — **условное** начальное наложение. Заменить на точно подогнанную модель, экспортировав её из `/wall-lab/`.

## Подготовить свой ракурс (обучение без нейросети)

1. Сделайте фото реального здания из предполагаемой зоны обзора, с естественными узнаваемыми деталями (кирпичи, окна, выступы). Снимки с другого ракурса потребуют отдельной подготовки.
2. В `/wall-lab/` нажмите **Открыть свой ракурс** и загрузите это фото. Оно будет центрировано и приведено к 1200x934, сохраняя пропорции с обрезкой краёв.
3. Подгоните геометрию стены и положение примыкания. Сохраните JSON, чтобы вернуться к настройкам.
4. Нажмите **Скачать эталон для OpenCV** (`reference.png`) и **Экспорт прозрачной стены PNG** (`wall-overlay.png`). Оба файла — 1200x934.
5. На том **же ПК** откройте **http://localhost:8000/track/setup.html**, выберите оба файла, **выделите мышью на эталоне узнаваемый участок башни**, нажмите «Добавить ракурс».
6. Новый ракурс сразу становится доступен для распознавания, перезапуск не нужен. Он хранится в `server/track_refs/tower`, а сведения о нём — в `server/track_zones.json`.

Новый ракурс **не** означает, что геометрия всей сцены автоматически восстановлена: для него нужно сделать своё совмещение стены. Распознавание не требует вручную отмечать ключевые точки.

## Для телефона

Сам фронтенд можно разместить на GitHub Pages (`/track/`), но OpenCV — это Python-сервер, а браузер телефона требует HTTPS для доступа к камере. Поэтому в телефоне нужно указать **публичный HTTPS API твоего сервера** в настройках страницы, а не `http://192.168...`.

На своём сервере необходимо развернуть `server` за обратным HTTPS-прокси и корректно настроить `CV_ALLOWED_ORIGINS=https://xintes.github.io`. Прежде чем открывать API наружу: установить ограничение частоты запросов, контроль максимального объёма данных и защитить или убрать `/api/track/train`. По умолчанию обучение разрешено только при запросах с localhost, либо с `CV_ADMIN_KEY`, если он задан. Видеокадры не сохраняются в API для распознавания.

## Ограничения

- Скорость зависит от процессора и связи. Обработка один раз в ~0.52 секунды, без передачи непрерывного видео; по результату изображение стабилизируется на экране. Сложные модели или сильное движение могут вызывать рывки.
- Фотографии нужны, но только **при подготовке обзорных зон**. Посетитель не делает фото: он направляет камеру и ждёт распознавания.
- Сразу после открытия сайта камерой надо направить на ту часть объекта, которую видит эталон.
- Фоновая загрузка библиотек Three.js у старого `/wall-lab/` требует интернет; `/track/` использует только обычный JavaScript.

## Файлы

- `server/tracker.py` — признаки, сопоставление, RANSAC, проверка качества.
- `server/track_zones.json` — список зон и ракурсов.
- `server/track_refs/tower/` — фото и PNG-наложения.
- `track/main.js` — камера, загрузка кадров, проекция стены.
- `track/setup.html` — локальное добавление новых ракурсов.
- `wall-lab/app.js` — редактор 3D-модели и экспорт прозрачного наложения.

Не заменяйте проект GitHub Pages этим сервером: GitHub Pages обслуживает только статические файлы, Python API туда не установится.
