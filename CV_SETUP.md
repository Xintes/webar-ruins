# Первый этап: WebAR без меток, OpenCV (без нейросетей)

Это **новый независимый режим** `cv/` внутри прежнего `webar-ruins`.
Исходный `index.html`, `app.js`, `settings.js`, `objects.js` и предыдущий AR-тест оставлены без изменений.

## Что уже реализовано

- Сайт в мобильном браузере получает изображение с камеры (Android Chrome, iOS Safari при наличии HTTPS и разрешения камеры).
- Отправляет **один JPEG примерно раз в 0,8 секунды**, с шириной не более 640 пикселей. Фото нигде не сохраняются на сервере.
- Сервер Python/FastAPI использует **только OpenCV**, **нейросети отсутствуют**.
- `desk_cube`: находит **кандидата на белый куб** по светлому контуру и тёмному фону. Учитывает область поиска, размер, форму, заполненность и яркостный контраст.
- `stone_wall`: сопоставляет кадр с заранее снятой фотографией через ORB + RANSAC + гомографию. Подходит для **фасада с отличительными деталями**.
- Рисует контур обнаруженной области и выводит **приблизительную экранную цепочку** из пяти кубиков через Three.js. Собственные `.glb` поддерживаются.
- Можно проверить **готовый JPEG/PNG** через кнопку «Проверить готовую фотографию» без камеры.

**Ограничение текущего этапа:** это **детекция и 2D-проекция**. Зелёный контур показывает, что OpenCV нашёл область. Модели пока привязаны к ней **в координатах экрана**. Это НЕ достоверная 6DoF-поза камеры и НЕ доказательство, что построение останется неподвижным при ходьбе. Для реальной 3D-привязки нужны калибровка камер, 3D-2D соответствия и `solvePnP`, а затем отслеживание между корректировками. Однотонный белый куб не всегда отличим от других белых предметов.

## Пошаговый запуск на Windows (компьютер)

1. Распакуйте ZIP. Важны новые папки `cv/`, `server/` и файл `CV_SETUP.md`.
2. Откройте терминал в корне проекта.
3. Создайте среду и установите зависимости:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt
```

4. Запустите сервер (из корня проекта):

```powershell
cd server
..\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

5. На компьютере откройте `http://localhost:8000/cv/` (это **один сервер**, и сайт, и API).
6. Поставьте чистый белый куб на **матовый контрастный фон**, лучше тёмный. Не клеить ничего на куб. Выберите «Белый кубик», нажмите «Включить камеру» или «Проверить готовую фотографию».
7. Если OpenCV увидит контур, появится зелёная обводка и цепочка виртуальных кубиков рядом с ним. Если нет — выводится объяснение, и виртуальная сцена исчезает.

Проверить живой API: `http://localhost:8000/api/health`.

**Важное замечание о телефонах:** `http://192.168.x.x:8000/cv/` обычно **не сможет включить камеру** на другом телефоне: браузер требует защищённый контекст. Для тестирования на Android/iPhone нужен сайт, открытый по **HTTPS** (в идеале сам Python-сервис за HTTPS-прокси), или отдельно размещённый GitHub Pages клиент и доступный через HTTPS API.

## GitHub Pages и отдельный сервер OpenCV

GitHub Pages выполняет только статические файлы. Python и OpenCV там запустить нельзя.

1. Загрузите новые `cv/`, `server/`, `CV_SETUP.md` в свой репозиторий `xintes/webar-ruins`, старые файлы оставьте.
2. Установите и запустите сервер там, где будет работать OpenCV (Windows/Ubuntu), проверьте `/api/health` внутри сервера.
3. Настройте HTTPS на **собственном домене API**, например `https://ar-api.example.org`. На этом этапе мы специально НЕ открываем порт наружу и НЕ делаем автоматический проброс на роутере: сначала локальная проверка, затем отдельное безопасное развёртывание.
4. В файле `cv/config.js` поменяйте `API_BASE: ""` на, например, `API_BASE: "https://ar-api.example.org"` (адрес — пример, не существующий сервер).
5. В `server/app.py` в переменной `CV_ALLOWED_ORIGINS` предусмотрена разрешённая страница `https://xintes.github.io`. При использовании другого домена дополните переменную окружения на сервере.
6. Сделайте Commit/Push. Тогда клиент будет по адресу `https://xintes.github.io/webar-ruins/cv/` и сможет работать с внешним HTTPS API.

Без доступного сервера на GitHub Pages появится подсказка о необходимости `API_BASE` — это ожидаемо.

## Как настраивать разные зоны (без маркеров)

Файл `server/zones.json` содержит зоны. У каждой собственный метод и параметры.

### 1. Белый кубик — геометрия и контраст

Зона `desk_cube`, метод `white_cube`. Для эксперимента ставьте куб на контрастную однотонную поверхность; старайтесь, чтобы рядом не было иных белых объектов. В `zones.json` при необходимости меняйте:

- `roi`: `[x, y, ширина, высота]` в долях кадра; позволяет искать только в определённой зоне экрана.
- `brightness_min`: насколько светлым должен быть объект (0–255); при плохом освещении понижайте осторожно.
- `saturation_max`: насколько нейтральным по цвету должен быть объект.
- `min_contrast`: требуемая разница яркости с фоном.
- `min_area_fraction`, `max_area_fraction`: допустимая доля кадра, занятая объектом.

Это фильтр-кандидат: он не отличит физический куб от любой похожей белой формы при неблагоприятных условиях. Реальная система должна дополнительно проверять грани, 3D-позу и согласованность во времени.

### 2. Башня/стена/руины — обучение на фотографии зоны

1. Снимите **только естественный фасад/каменную поверхность** в планируемой зоне обзора, с фактурой, окнами и различимыми элементами. Никаких физических меток.
2. Поместите фотографию как `server/references/stone_wall.jpg`.
3. В интерфейсе выберите «Фасад/руины».
4. `ORB` находит характерные детали в эталонной фотографии и на кадре посетителя. `RANSAC` отбрасывает неверные соответствия и строит перспективное преобразование для **приблизительно плоской** сцены.
5. Для другого фасада добавьте запись с новым уникальным ID в `server/zones.json` и свою фотографию в `server/references/`.

При нескольких ракурсах одного объёмного здания в будущем потребуется несколько референсов и 3D-карта; одна гомография не решает задачу объёмной реконструкции.

## Массив виртуальных объектов

Правьте `cv/config.js`, массив `arrays`. Синтаксис **такой же, как в предыдущем режиме**:

- `count` — сколько штук;
- `start` — координаты первой;
- `step` — расстояние и направление;
- `type` — `box`, `sphere`, `cylinder`, `cone`, `glb`;
- `size`, `colors`, `rotation` — параметры примитивов;
- `file`, `scale` — параметры `.glb`.

Сейчас единицы `start`, `step`, `size` — **доля ширины найденного ориентира на экране**, не метры. Для своей модели экспортируйте статический GLB из Blender в `cv/models/my-object.glb` и включите в `cv/config.js` группу «Собственные модели».

## Проверка и ограничения безопасности

```powershell
# Из корня проекта, с активной/установленной .venv:
.\.venv\Scripts\python.exe -m unittest discover -s server/tests -v
```

Кадры обрабатываются в оперативной памяти, на диск не записываются. Всё же при публичном API обязательно добавить TLS, лимит запросов, ограничение доступа и нагрузочное тестирование, прежде чем запускать массовую экскурсию. 0,8 секунды между запросами — стартовый компромисс для слабых телефонов, но этого недостаточно для плавной истинной AR-привязки при быстром движении камеры.

Мы **не гарантируем работу на каждом телефоне и с любой плохой камерой**. Для надёжности нужны испытания на конкретных устройствах, учитывающие размытие, освещение, экспозицию, фокус, скорость сети и требования браузеров. Резервный режим — проверка фотографии и подсказка сменить точку обзора.
